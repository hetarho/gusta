# Optional usage measurement

Enable with `gusta vibe settings --set usage-measurement=true`; disable with `usage-measurement=false` (the default). Missing keys use the default. No extra model request or price lookup is made. Disabled runs retain their existing output and do not collect or write measurement records.

Enabled CLI-managed adapter invocations record provider-reported tokens and models in local Git runtime `gusta/v1/usage/<run>/`. Completion saves machine-readable `run.json` and human-readable `report.md`; native reports use separate `native-usage/<tag>.report.json` and `<tag>.report.md` files. Existing JSON path fields keep their meaning; `reportFile` names the Markdown file, `reportLink` is its clickable local link, and `chatSummary` contains the concise summary and link. Reports expose the measurement period/baseline, session and model scope, input/output/cache-read/cache-creation tokens, known/unknown coverage and provider-reported USD when available. Records contain attribution (role and task/unit when supplied), random local session aliases and measurements, never prompts, source, tool payloads or provider session identifiers. Existing execution logs have their separate retention policy.

The top-level initiating `gusta-start`, `gusta-self-improve` or `gusta-self-improve-remote` conversation must deliver the usage summary and clickable Markdown report link in its final **chat response**, including no-work, parked and error exits that return control. A saved file, JSON response or CLI stderr alone is not delivery to the user. The parent awaits detached/background completion, retrieves the returned measurement from the terminal event/status/result, then relays it; child workers do not create another parent report. Existing owner reports may link it under `checks`. Missing/unsupported measurements still produce an honest unknown/partial report when runtime is writable. A save failure returns a null path and an explicit report error; continue the task and tell the user the file could not be saved. Disabled runs create no measurement files or extra usage messages.

Claude terminal `result.usage` wins over streamed assistant snapshots, which are deduplicated by message ID and used only as partial fallback. A zeroed crash result preserves prior input/cache evidence; streamed output placeholders remain unknown. These tokens cover the main loop; native/subagent usage is outside this token total. Claude input excludes cache read and creation, so processed input is their sum. Reported USD is recorded only when supplied; resumed Claude cost is marked cumulative with unknown run baseline and excluded from run USD totals. It is not invoiced cost or subscription quota. See [Claude accounting scope](https://code.claude.com/docs/en/agent-sdk/cost-tracking).

Codex `turn.completed` usage wins over `token_count` snapshots. Both terminal and total counters are session-cumulative: the latest replaces earlier snapshots, while last-turn counters are never added to their cumulative total. Resumed invocations subtract the previous same-run session snapshot; missing baselines and decreasing/reset counters remain unknown. Codex processed input is the provider's raw input total, already including cache read; its JSON `input` field is input minus cache read, following the provider's non-cached-input convention. Reported cache writes are shown independently and are not added to that denominator. Cache creation remains unknown when unreported. No partition of Codex write tokens is inferred. See [Codex event accounting](https://github.com/openai/codex/blob/main/codex-rs/exec/src/event_processor_with_jsonl_output.rs).

Missing/unsupported counters remain unknown, distinct from reported zero. Failed, interrupted, malformed and truncated streams retain available evidence as partial; a killed adapter may leave no record and the host reports that gap. Aggregates sum known observations and expose coverage rather than presenting unknown usage as zero. Cache-read share is cache-read tokens / known processed-input tokens, and is unknown when that denominator is incomplete or zero.

Adapter collection covers GUSTA's shared Claude/Codex adapter (loop units, work workers/reviewers, scouts and A/B sessions). Loop/work/scout reports aggregate their run; A/B reports each headless session independently. Observed main-loop assistant request counts and peak processed input are retained when available, without inferring them from aggregate totals. Custom adapters, initiating host/orchestrator calls, native child sessions and preflight probes are outside this adapter total. Their usage is not zero.

Model groups identify observed main-loop models. A multi-model invocation is grouped as `A + B`; its aggregate tokens/cost are not split into unsupported per-model allocations. Requested model names are labeled `requested:... (actual unknown)` when the provider never reports an actual model.

For native Claude conversations, enabled `gusta-start`, `gusta-manage-work`, `gusta-self-improve`, `gusta-self-improve-remote` and `gusta-showcase` entry points use `vibe usage start --tag <tag> --marker <literal32hex>` before work and `vibe usage report --tag <tag>` at completion. The top-level initiating conversation owns that baseline/report; same-conversation nested skills reuse it, and native/host-managed children skip duplicate reporting. The literal marker selects the exact session from that checkout's local logs; `--session <id>` can select a known session explicitly, and `--project-dir <exact-log-dir>` selects an explicit log directory. Start records a baseline; report measures subsequent observations from that exact parent session and checkout. Child logs under the selected session's `subagents/` may have a different worktree cwd only when their session ID matches, `isSidechain` is true, and the agent ID matches the filename; unproven rows are excluded and coverage is partial. No unrelated log directories are scanned. An explicit `vibe usage report --session <id>` without a baseline reports full recorded session history. Native artifacts use a separate runtime scope and never merge with adapter totals; overlapping parent/child reports are never additive. The current final reply is outside the report snapshot; unsupported hosts and missing/truncated logs remain unknown/partial.

Fresh sessions and cache hits alone do not establish savings: that requires matched workloads and a controlled baseline. No current prices or savings estimates are inferred.
