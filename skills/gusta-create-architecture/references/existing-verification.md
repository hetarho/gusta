# 기존 검증 대조

ARCH의 검증 단계를 정할 때 프로젝트에 이미 검증 지침·스크립트·CI가 있으면 읽는다.

- 기존 규칙이 task/batch/CI 기본 단계와 다르면 범위·명령·조건을 보존하며 기본 단계로 맞추는 안을 추천한다. 주체·시점 등 정책이 달라지면 실제 원문·변경안·영향을 보여 주고 물은 뒤 개정한다(이미 승인한 변경은 재질문하지 않고, 맡김은 그 차이를 parked). 조건부 검사의 적용 조건·경로 선택법도 보존한다. 미지원 프로젝트 정책을 단계 이동으로 조용히 약화하지 않는다.
- 긴 task 검사는 실제 위험·의존성과 실측으로 줄이거나 다른 단계로 옮긴다.
- 지침의 필수 검사와 실제 스크립트를 검사별 주체·단계·조건·입력·중복·재사용 조건으로 대조한다. 독립 검사가 한 스크립트에 묶여 부분 성공을 잃으면 프로젝트 소유 JSON 계획을 검증 결정의 `plan:` 하위 줄 백틱 경로로 연결한다(스키마·입력·실행은 [검증 절차](../../gusta-start/references/verification.md)). 기존 단계 명령으로 충분하면 계획 파일을 만들지 않는다. 설명문을 실행 명령으로 추측하지 않는다.
- 승인된 별도 정책이 없으면 단계가 없다는 이유로 태스크에 전체 verify를 붙이지 않는다. 프로젝트의 명시적 검증 의무는 없애지 않는다.
