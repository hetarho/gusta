# 프로젝트 규칙 대조

패키지 동작과 프로젝트가 지금 요구하는 절차를 대조하고, 차이는 현재 프레임워크 기본 절차에 맞추는 안을 권유해 괜찮은지 묻는다. SETTINGS는 CLI 실행값의 정본일 뿐 프로젝트 정책 변경 승인이 아니며, 승인 전에는 적용되는 지침을 지킨다.

업데이트는 전체를 조사한다. 설정 변경·초기화·ARCH 개정에서는 그 작업에 적용되는 지침과 바꾸려는 주제의 활성 규칙·실행 근거·연결 문서만 조사하고, 범위가 불명확하면 inventory로 넓힌다.

## 1. 조사 범위와 완결성

- `gusta upgrade-context --all --out <대상 프로젝트 밖의 세션 임시 파일>`을 한 번 실행하고, 그 파일(한 줄에 entry 하나)을 나눠 읽으며 처분을 기록한다. 확인용으로 다시 부르지 않고, 설치·이관 뒤와 실제 반영 전에만 원문·해시를 다시 확인한다.
- `coverage.inventoryComplete`가 true여야 목록 조사가 끝난 것이다. `policyReviewed:false`·`errors`·읽기 실패·경계·참조 미확인을 검토 완료로 세지 않는다.
- 모든 entry에 처분과 이유를 남긴다: 활성 규칙·설명/참조·구현/CI 근거·생성물/외부 소유·역사 기록·미확인. CLI의 kind·scope·disposition은 단서일 뿐 판정이 아니다.
- 루트·중첩 경로의 AGENT.md·AGENTS.md·CLAUDE.md, README·CONTRIBUTING·spec·임의 위치의 운영 문서, 목록에 있는 낯선·숨김·ignored 파일까지 본다. 규칙 블록 전체(조건·예외·의무·시점·주체)와 링크·include한 로컬 문서·CI/스크립트·설정·생성 원본까지 읽고, 파일명·키워드가 없다는 것만으로 무관하다고 판정하지 않는다. 읽을 수 없는 저장소 밖 참조는 한계와 영향받는 동작을 남긴다.
- 제3자·생성물·완료 태스크/보고서 같은 역사 기록은 이유를 확인해 제외하고 고치지 않는다. 활성 문서가 현재 규칙으로 인용하면 그 파일만 확인하고, 생성 문서의 규칙은 원본을 찾는다.
- 중첩 checkout·명시된 경계 안은 별도 범위로 조사하거나 미확인으로 남긴다. 반영 전에는 연결된 worktree의 활성 세션·문서 소유권·미커밋 작업을 확인하고 다른 세션의 문서·ref를 바꾸거나 plan-sync/plan-push하지 않는다(PID가 안 보인다고 종료로 보지 않는다). 소유가 불명확하면 사용자/소유자와 조정한다.

검토표: 경로·근거 줄/블록·적용 범위·현재성·참조 대상·대조 결과·미확인 이유. 목록 완독과 대조 완료를 구분한다.

## 2. 규칙·설정·실제 동작 대조

- 같은 주제이며 적용 경로·작업·시점이 겹치는 규칙만 대조한다. 하위 경로 예외, 설명과 의무, 과거 기록과 현재 정책을 한 규칙으로 합치지 않는다.
- `settings`의 값·source·default·legacy와 버전 변경을 본다. 누락 키의 새 기본값도 동작이지 승인된 선택이 아니며, 이전 동작을 확인할 수 없으면 미확인이다.
- 설정 소비 코드·package 스크립트·CI/workflow·호출 플래그와도 대조한다. 다르다는 것만으로 문서를 코드에 맞추지 않는다.
- 활성 태스크 acceptance는 참조한 테스트·스크립트가 실제로 하는 범위로 대조한다. 전체 검사를 done 조건으로 요구하면 태스크의 변경 영향 검사+인계와 최종 관문의 전체 범위 실행·증거를 추천하되, 완료 시점/주체 변경은 승인받아 활성 계약도 함께 고친다. 미실행 검사를 통과로 쓰거나 필요한 범위를 없애지 않는다.
- ARCH 검증 결정에 task/batch/CI 단계 선언이 없거나(lint 검토 후보) 태스크 단계에 느린 명령이 있으면(`vibe status`의 `taskChecks.slow`, runtime timings 근거) 같은 주제의 실제 차이다 — 단계 선언과 1분 넘는 검사의 batch 이동을 3절대로 권유한다.
- [제품 지원 정책](../../gusta-create-architecture/references/product-support.md)의 현재 결정을 실제 테스트·CI 행렬과 대조해 범위 밖 비용과 미확인을 보여 준다.
- 테스트 감사(필수): `upgrade-context.testPolicy` 후보와 실제 스크립트 호출망·테스트 설정·대표 테스트·검사 계획·runtime timings를 읽어 유지/축소/agent 대체/CI 이동/미확인으로 처분한다. 태스크마다 도는 전체 스위트, 같은 SHA의 중복 CI/릴리스, 비용 큰 fixture·재시도, 소스 문자열/구현 추종 테스트, 선언하지 않은 브라우저 행렬을 찾는다. agent AC를 더하면 대체할 E2E/명령 범위의 제거·축소안과 비용·증거/담당자를 함께 내고, 둘 다 유지하는 안을 기본으로 삼지 않는다. 시간 자료가 없으면 unknown이며, 이름/개수만으로 검사를 지우지 않는다.
- 검사마다 명령·범위·주체·단계/시점·적용 조건·입력·성공 재사용 조건을 실행 근거와 대조한다. package 스크립트·CI의 중첩 호출에서 같은 범위의 중복 실행을 찾고, 시간에 민감한 성능 검사가 병렬 검사와 자원을 다투면 분리한다. 문서/SSOT 변경은 실행 입력·빌드 설정·검증 환경에 미치는 영향으로 판정한다(일괄 재실행·일괄 제외 없음).
- **검사별 연결 완료 조건**: 필수 범위가 ARCH 단계별 명령 또는 [검사별 계획](../../gusta-start/references/verification.md)의 JSON·ARCH `plan:`으로 실행되고, 대조 결과와 중복 제거·성공 재사용·무효화 근거가 활성 검증 지침에 남아야 한다. `declared:false`·`partial:true`·미연결 명령이 남으면 완료가 아니다. 의무 범위를 보존하는 실행 정리는 진행하고 반복·품질 범위·조건·주체/시점 변경은 3절대로 승인받는다. 코드 정리는 엔지니어 태스크로 잇고 미완료로 남긴다.
- 브랜치/기획 발행·검증/리뷰·배포·권한/MCP·정리/보존·자동화/위임은 시작점일 뿐이다. 문서의 실제 규칙에서 주제를 더 찾는다(예: PR 정책이 spec 발행에도 적용되는지, 필수 검사의 시점·주체도 계약인지).
- 결과는 동일·상호보완·범위가 다른 예외·직접 충돌·패키지 미지원·판단 불가로 나눈다. 설정값이 같아도 더 넓은 프로젝트 제약이 남으면 해결이 아니다.

## 3. 판단·반영·재검토

- 자동 적용은 동작이 같다는 근거가 있는 사실/표기 정리와 구조 이관뿐이다. 조건·예외·수치·부정·의무 수준·실행 주체/시점이 바뀌면 정책 선택이고, 오래됐거나 FORMAT diff의 extra라는 것만으로 지우지 않는다.
- 정책 선택은 겹치는 범위, 양쪽 원문, 유효 설정과 실제 실행, 바뀔 파일·값·주체/시점·영향, 유지할 때의 지원 한계를 모아 **현재 프레임워크 기본 절차에 맞추는 안을 추천하고 "이렇게 맞춰도 괜찮을까요?"라고 묻는다.** 이미 구체적으로 승인한 변경은 다시 묻지 않는다. 판단할 수 없거나 답할 사람이 없으면 영향받는 작업과 필요한 결정을 parked로 남긴다(맡김의 추천안 자동 채택으로 대신하지 않는다).
- 승인된 선택만 SETTINGS와 영향받는 모든 활성 문서·범위별 지침에 반영한다(SSOT 정책 변경은 gusta-update-ssot). 변경한 문서가 인용하는 규칙·진행 중 작업도 재확인하고 역사 기록은 다시 쓰지 않는다.
- 설정·문서만으로 구현할 수 없는 선택은 지원되는 것처럼 보고하지 않고, 필요한 CLI/CI 변경을 따로 제안한다. 자동 발행·배포·삭제·권한 변경으로 우회하지 않는다.
- 승인된 테스트 정책의 script/CI/test 정리는 엔지니어 태스크로 잇는다. 업데이트 담당이 코드를 지우거나 계획만 남기고 끝났다고 말하지 않으며, 최신 버전 재설치에서도 미완료 감사·중복 비용을 다시 확인한다.
- 새 inventory와 diff로 반영 범위·근거·링크·제외·미확인을 재검토한다. lint 통과는 정책 일치 증거가 아니다. 최종 보고에 검토 범위·남은 충돌/미확인·다음 결정을 적고, 미확인이 있으면 충돌이 없다고 단정하지 않는다.
